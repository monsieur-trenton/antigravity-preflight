# Plan Review: Scratch Directory Cleanup

## Blocking issue: the run identifier does not identify a run

The plan relies on each directory's tag to tell runs apart, but every run uses the **same fixed tag, `nightly`**. So the tag cannot tell one run's directories from another's.

Combine that with the plan's own statements:

1. More than one build run can be going at once.
2. Cleanup removes every directory whose tag matches the run's own identifier.
3. A run must never remove directories made by another run.

Suppose runs A and B overlap. When A finishes, its cleanup selects every directory tagged `nightly`. That includes B's directories, which B may still be using. A then calls `rm -rf` on them. This breaks the stated rule directly. It is also likely to make B fail partway through, or produce corrupt output.

The service account does not prevent this. Both runs presumably use the same unprivileged account, so A has full permission to delete B's directories. The deletion log records the problem after the fact but doesn't stop it. Each entry would just show `nightly` and a path, with no way to tell which run made the directory.

## Required changes

- **Make the identifier unique per run.** Examples: a UUID, a CI build ID plus attempt number, or hostname + PID + start timestamp. Generate it once at run start and use it both for tagging and for cleanup. If the `nightly` label is useful, keep it as a separate field (for example `job=nightly, run=<uuid>`).
- **Better still, have each run track its own directories.** Give each run a parent directory such as `/var/cache/app/<run-id>/`, or have it record the exact paths it created. Cleanup then deletes only that parent or that list, rather than scanning for matching tags. This removes any dependence on tag matching.

## Suggestions (not blocking once the above is fixed)

- Create directories atomically with `mktemp -d` under the run's parent, so names can't collide.
- Before running `rm -rf`, check that the resolved path is still under `/var/cache/app` and is not a symlink. This guards against path or symlink mistakes.
- Log the unique run ID with each deletion so the audit trail can show which run did what.
- Plan a separate sweep for directories left behind by crashed runs, for example ones older than N hours whose run is no longer active. Normal cleanup doesn't cover these.

## Summary

As written, the plan breaks its own rule whenever two runs overlap. The tag that is supposed to prevent cross-run deletion is the same for every run, so one run's cleanup will delete another run's directories.

VERDICT: NO_GO
