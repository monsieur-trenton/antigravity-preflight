## Review

**Problem: the plan covers only the sources that changed, not all four.**

- **The rule:** the report must cover each of the four supplied sources exactly once, and the checker rejects any report whose coverage set differs from the supplied inventory.
- **What the plan does:** it writes one section per source *that changed in the diff*.
- **What that produces:** a typical diff changes only one or two of the four sources, so a typical report covers one or two sources and leaves out the rest.
- **What happens next:**
  1. The coverage set does not match the inventory, so the checker rejects the report.
  2. Even before that, a report with a missing source is marked INCOMPLETE and is never recommended for readiness.

This isn't an edge case. Following the plan as written produces a non-compliant report in the normal case. Full coverage happens only when all four sources change in the same diff.

**Required fix:** iterate over the supplied inventory of four sources, one section per source, rather than over the diff. Each section still lists the source's SHA-256 and line count, and both can be computed whether or not the source changed. If change status matters, record it as a field in each section (e.g., "changed: yes/no") instead of using it to decide which sections exist.

**Optional hardening:** before submitting, check that the set of sources covered equals the inventory, with no omissions and no duplicates. That catches the "exactly once" violation before the checker does.
