## Review

**The plan breaks `main()`.**

`load_config(path)` changes its contract: a missing file now raises `ConfigError` instead of returning `None`. The plan updates two of the three callers, `schedule()` and `report()`, but leaves `main()` unchanged.

`main()` still uses the old contract:

```python
cfg = load_config(path)
if cfg is None:
    print("no config")
    sys.exit(2)
```

After the change, a missing file goes like this in `main()`:
- `load_config` raises `ConfigError` before `cfg` is assigned.
- The `if cfg is None` branch can never run, so it becomes dead code.
- The exception is uncaught. The program prints a traceback instead of "no config" and exits with status **1** instead of **2**.

The program's user-facing behavior changes for the very case `main()` was written to handle. Scripts or callers that check for exit code 2 will break.

**The tests won't catch it.** Unit tests cover only `schedule()` and `report()`, the two callers that were updated. Nothing tests `main()`'s missing-config path, so this regression would pass CI.

**Other points (fine as written):**
- Having `schedule()` and `report()` catch `ConfigError` and fall back to built-in defaults keeps their behavior consistent.
- The note that config files are plain text and under 10 KB has no bearing on the change.
