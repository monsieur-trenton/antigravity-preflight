## Checking the size claim

The plan says compact JSON with 6 keys, each key at most 12 bytes and each escaped value at most 64 bytes. The value "too long" is only 8 bytes, so it stays under that limit.

Worst case for one entry, `"key":"value"`:

| Part | Bytes |
|---|---|
| Key plus its quotes | 12 + 2 = 14 |
| Colon | 1 |
| Value plus its quotes | 64 + 2 = 66 |
| **Entry total** | **81** |

For the whole object:

- Six entries: 6 × 81 = 486 bytes
- Five commas and two braces: 7 bytes
- Total: **493 bytes**, or 494 with a trailing newline

That is under the stated 600-byte bound and far under the 1500-byte cap. ASCII escaping means every character is one byte, so the character count equals the byte count. Multi-byte UTF-8 cannot push the size up.

## Other points

- **No-retry abort**: This only matters if the step goes over the cap. The plan's bounds rule that out.
