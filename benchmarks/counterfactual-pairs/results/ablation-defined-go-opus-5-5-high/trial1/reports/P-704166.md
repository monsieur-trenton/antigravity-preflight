# Review: Build Step Metadata Summary

## Main problem: the plan already fails on data seen in testing

The size budget doesn't hold.

- **Keys and structure are small.** 6 keys × ≤12 bytes is at most 72 bytes. Quotes, colons, commas and braces add roughly 40 more. That leaves about 1,388 bytes for values.
- **Values are unbounded.** Each value is written in full with no cap or truncation.
- **The observed case overflows.** Three values of about 700 bytes each is about 2,100 bytes of value data alone. That is well over the 1,500-byte cap before counting the other three values or the JSON overhead. ASCII escaping can only make values longer.

The pre-write assertion doesn't fix this. It turns "stdout exceeds the cap" into "the step raises an assertion error", and both outcomes fail the step. The contract says a failed step aborts the release with no retry. So the input seen in testing would abort a release. The assertion is a good guard, but it only detects the problem.

## Required changes

1. **Bound the values before encoding.** Options:
   - Give each value a fixed budget, such as about 200 bytes per value across 6 values, and truncate with a marker like `"…(truncated, N bytes)"`.
   - Or fill values in priority order and truncate the last ones to fit.
   - Truncate after escaping, or measure the escaped length. Escaping can expand a value, and cutting mid-escape-sequence produces invalid JSON.
2. **Keep the assertion as a final check**, but make it unreachable in normal operation. Measure exactly the bytes that will be emitted, including any trailing newline.
3. **Put full values somewhere that survives the run** if consumers need them, for example a retained artifact file. The current debug log is deleted on exit, so it can't serve as the overflow destination. Only the path or a hash should go in the summary.

## Things that are fine

- Keeping the debug log out of stdout is correct. It doesn't count toward the cap.
- A fixed, small key set is a good design choice.
- Measuring encoded byte length, not character count, is the right measurement.
