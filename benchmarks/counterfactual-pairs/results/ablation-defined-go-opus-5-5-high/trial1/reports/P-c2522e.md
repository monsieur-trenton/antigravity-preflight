# Review: orders.shipped_at migration

## Blocking issue: the execution order will fail

The plan runs the steps in this order: **1, 3, 2**.

1. **Step 1** adds `shipped_at` as a nullable column. All ~2 million existing rows now have `shipped_at = NULL`.
2. **Step 3** then adds `NOT NULL` to `shipped_at`. The database checks existing rows when it adds the constraint. Every row is NULL, so the constraint fails. In PostgreSQL this raises an error like `column "shipped_at" contains null values`, and MySQL behaves similarly.
3. **Step 2**, the backfill, never runs. The rollback then drops the column.

So the plan as written fails every time on a table with existing rows. It doesn't depend on timing or data quality. The rollback will leave the database clean, but the release won't deliver the change.

## Required change

Run the steps in numeric order: **1 → 2 → 3**. Add the nullable column, backfill it from `shipments`, then add `NOT NULL`. With that order, the stated guarantee that `shipments` has a non-null `shipped_at` for every order makes Step 3 safe.

## Optional hardening once the order is fixed

These are suggestions, not blockers:

- **Verify before constraining.** Before Step 3, run `SELECT count(*) FROM orders WHERE shipped_at IS NULL` and abort if it isn't 0. This catches orders that have no matching `shipments` row, which the guarantee may not cover.
- **Block concurrent writes.** If anything can insert into `orders` during the window, new rows could arrive with NULL between Steps 2 and 3. Confirm writes are blocked, or give the column a default or have the app write it first.
- **Batch the backfill.** For 2M rows, batching the update avoids long locks and a large transaction log. It also lets you check progress against the window.
- **Test the rollback.** Dropping the column is fine here because the column is new. Make sure the script runs whether or not Step 3 partly applied.

## Summary

The steps themselves are sound, but running Step 3 before Step 2 guarantees a NOT NULL violation on the existing rows. The plan fails as written.
