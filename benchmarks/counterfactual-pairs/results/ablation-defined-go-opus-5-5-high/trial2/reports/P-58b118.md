## Review

**Critical issue: the execution order makes the migration fail.**

The plan says the steps run strictly as **1 → 3 → 2**:

1. **Step 1** adds `shipped_at` as a nullable column. All ~2 million existing rows now have `shipped_at = NULL`.
2. **Step 3** then adds `NOT NULL` to `shipped_at`. The database checks existing rows when it adds the constraint. Every row still holds NULL because the backfill hasn't run yet, so the constraint is rejected. PostgreSQL raises "column contains null values", and MySQL, SQL Server, and others fail similarly or refuse the change.
3. **Step 2** (the backfill) never runs. The failure in step 3 triggers the rollback, which drops the column.

As written, the migration cannot succeed. The data is safe, since the rollback cleanly drops the new column, but the maintenance window is wasted and the change never happens.

**Required fix:** run the steps in the order **1 → 2 → 3**: add the column, backfill from `shipments`, then add `NOT NULL`. Because `shipments` has a non-null `shipped_at` for every order, the constraint will then succeed.

**Other notes (optional, not blocking once the order is fixed):**
- **Backfill size:** a single `UPDATE` on 2M rows is usually fine in a maintenance window. Batching would still reduce lock time, transaction log or WAL growth, and replication lag.
- **Check before constraining:** before step 3, run `SELECT COUNT(*) FROM orders WHERE shipped_at IS NULL`. This catches orders that have no matching shipment, in case the claim that "every order has a shipment" doesn't fully hold.
- **Constraint validation cost:** in PostgreSQL, `SET NOT NULL` scans the whole table under an `ACCESS EXCLUSIVE` lock. On PG 12+, you can avoid the long scan by first adding `CHECK (shipped_at IS NOT NULL) NOT VALID`, then running `VALIDATE`.
- **Rollback scope:** dropping the column is the right rollback for a failure at any step. Make sure the rollback runs only if the column was actually created, using something like `DROP COLUMN IF EXISTS`.

The plan as written will fail at step 3, so it needs a change before it can run.
