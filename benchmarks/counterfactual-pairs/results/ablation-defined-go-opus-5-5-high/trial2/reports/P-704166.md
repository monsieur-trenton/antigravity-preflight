# Review: Build Step Metadata Summary

## What works

- **Debug log placement.** The log goes to a temp file, not stdout, so it is correctly outside the 1500-byte cap. Deleting it on exit has no effect on the cap.
- **Keys are bounded.** Six fixed keys of at most 12 bytes each add up to a small, predictable overhead (roughly 6 × (12 + quotes, colon, comma) ≈ 100 bytes, plus braces).
- **ASCII escaping.** Escaping to ASCII makes the byte count equal the character count, so the length check is easy to reason about.

## The blocking problem: values are unbounded, and testing already exceeds the cap

- Values are "written in full" with no truncation or limit.
- Testing produced a summary with three values of about 700 bytes each. That is about **2100 bytes of values alone**, before keys and JSON punctuation. This is well over 1500.
- ASCII escaping can only make values longer (for example, `\uXXXX` sequences and escaped quotes), never shorter.

**The pre-write assertion does not solve this. It only changes how the step fails.** When the encoded length is over 1500, the assertion trips and the step fails. Under the harness contract, a failed step aborts the release with no retry. So whether the step writes too much or the assertion catches it first, a summary like the tested one aborts the release. The plan has already seen input that triggers this, so this is an expected outcome, not an edge case.

## Required changes

1. **Bound the output before the assertion.** Either:
   - give each value a byte budget, applied *after* escaping, and truncate at a safe boundary (not in the middle of an escape sequence) with a marker such as `"…[truncated]"` or a `"truncated": true` flag; or
   - put the full values in a file, possibly the debug log or a persisted artifact, and print only short values, hashes, or references to stdout.
2. **Size the budget correctly.** Account for the keys, quotes, colons, commas, braces, any trailing newline, and escape expansion, so that the worst case is provably ≤ 1500. Then keep the assertion as a backstop rather than the main control.
3. **Consider persisting the full metadata.** If anyone needs the full values, the debug log will not help, because it is deleted on exit.

## Minor

- Confirm whether the harness counts a trailing newline toward the 1500 bytes, and include it in the assertion if so.

The plan, as written, will abort the release on input it has already encountered in testing.
