# Plan Review: `load_config` raises `ConfigError` instead of returning `None`

## Blocking issue: `main()` breaks on a missing config

The plan changes what `load_config` does on a missing file, but leaves one of its three callers depending on the old behaviour.

- **Before:** a missing file returns `None`. `main()` sees `cfg is None`, prints "no config" and exits with status 2.
- **After:** a missing file raises `ConfigError`. `main()` never catches it, so the exception goes all the way up. The user sees a traceback instead of "no config", and the process exits with Python's default status 1 instead of 2.
- **Side effect:** the `if cfg is None` check in `main()` can no longer be true, so it becomes dead code.

Anything that relies on exit status 2 to mean "no config" will now get the wrong answer. That includes shell scripts, CI jobs, systemd units and wrapper tools. The plan as written breaks this path, which is why the verdict below is NO_GO.

**Fix:** update `main()` along with the other two callers:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")
    sys.exit(2)
```

Then remove the `None` check.

## Why the tests won't catch it

The existing unit tests cover only `schedule()` and `report()`. `main()` has no test, so this regression would pass CI. Add a test that runs `main()` with a missing config path and checks two things:
- it prints "no config"
- it exits with status 2 (for example, `pytest.raises(SystemExit)` and check `.code == 2`)

## Smaller points (not blocking)

- **Update the existing tests.** Any test for `schedule()` or `report()` that mocks `load_config` to return `None` is now testing a path that can't happen. Change those mocks to raise `ConfigError`, and make sure each function's fallback to the defaults is tested.
- **Define "missing" exactly.** State whether `ConfigError` covers only `FileNotFoundError`, or also permission errors and unreadable files. Catch the narrowest error that fits, so other I/O failures aren't silently hidden behind defaults.
- **Keep the original exception.** Use `raise ConfigError(...) from e` so the underlying error stays visible when debugging.
- **Check for other callers.** The plan lists three callers. A quick `grep` for `load_config` will confirm there are no others, such as scripts or plugins, that still check for `None`.
- The file being plain text and under 10 KB doesn't affect this change.

## Summary

Moving `schedule()` and `report()` to catch `ConfigError` is fine. But leaving `main()` unchanged breaks its documented behaviour: it should print "no config" and exit with status 2, and instead it will crash with a traceback and exit with status 1. Update `main()` to catch `ConfigError` and add a test for that path.

VERDICT: NO_GO
