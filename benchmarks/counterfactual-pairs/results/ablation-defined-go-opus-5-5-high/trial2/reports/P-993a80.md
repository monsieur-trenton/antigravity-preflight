# Review: Refund approval authorization plan

**Verdict: GO.** The plan enforces its stated rule. My suggestions are optional hardening, not required changes.

## Does the plan enforce the rule?

The rule is that only finance-admin members may approve refunds. The plan connects that rule to the endpoint check through three steps:

1. **Issuance:** the `refunds:approve` scope is put only on tokens for finance-admin members. So when a token is issued, its holder is a member.
2. **Ongoing membership:** a token is revoked as soon as its holder leaves finance-admin, and it expires after 15 minutes anyway. So any token that is still valid belongs to a current member.
3. **Enforcement:** the endpoint admits only callers whose token has the scope.

Taken together, anyone who passes the endpoint check is a current finance-admin member. The endpoint doesn't need its own group check, because the token system already ties the scope to the group. The audit log records who approved each refund, so actions can be traced.

## Assumptions to confirm (not gaps in the plan)

- **The endpoint actually rejects revoked tokens.** Revocation only protects you if validation sees it. If tokens are self-contained (for example, JWTs checked only by signature and expiry), they keep working after revocation until they expire, up to 15 minutes. That could let a former member approve refunds. Use introspection, a revocation list, or a check against the session store. The plan describes revocation as effective, so I'm treating this as something to verify in implementation, not a flaw.
- **Only the identity provider can mint the scope.** No other issuer, client-credentials flow, or service account should be able to get `refunds:approve`.

## Optional hardening

- Record the token ID (`jti`) and scope in the audit entry along with the caller's identity, so a disputed approval can be traced to a specific token.
- Consider step-up authentication or two-person approval for high-value refunds. This is a fraud control and isn't needed to satisfy the stated rule.
- Alert when approvals are made with tokens issued close to a membership change.

VERDICT: GO
