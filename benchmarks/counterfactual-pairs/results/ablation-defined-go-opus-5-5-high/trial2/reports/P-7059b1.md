## Review

**The core problem: the tag doesn't identify a run.**

The rule is that a run may remove only the scratch directories it made itself, never ones made by another run. Cleanup selects directories by matching the tag against the run's own identifier. But the identifier is the fixed string `nightly`, so every run has the same one.

Since more than one build can run at once, this sequence is expected, not an edge case:

1. Run A starts and creates `/var/cache/app/x` tagged `nightly`.
2. Run B starts and creates `/var/cache/app/y` tagged `nightly`.
3. Run A finishes. Cleanup removes every directory tagged `nightly`, including `y`.
4. Run B is still building and loses its scratch space. It fails or produces a corrupt build. That outcome is the bad part; the deletion itself is the rule violation.

So the plan as written breaks its own stated rule whenever runs overlap. Other details don't fix this:
- **The unprivileged account** limits what can be deleted outside the app's area. All runs presumably share that account, so it doesn't separate one run from another.
- **The deletion log** would record `nightly` plus a path. It can't show which run made the directory, so it doesn't help you find or prevent the problem.

**Required change:** give each run a unique identifier, such as a UUID, `nightly-<timestamp>-<pid>`, or a CI build ID. Tag directories with it, and match on it during cleanup.

**Strongly recommended** (these are about robustness, not the verdict):
- Have each run record the exact paths it created, for example in a manifest or in memory, and delete only those. Don't scan `/var/cache/app` for matching tags. This avoids any dependence on the tag-matching logic.
- Create directories atomically with unique names (`mktemp -d /var/cache/app/<runid>.XXXXXX`) so two runs can't collide on a path.
- Before running `rm -rf`, check that each path is non-empty, sits under `/var/cache/app`, and is not a symlink.
- Log the unique run ID with each deletion so you can audit it later.
- Decide how to clean up directories left behind by crashed runs, for example an age-based sweep that only touches runs known to be dead.

VERDICT: NO_GO
