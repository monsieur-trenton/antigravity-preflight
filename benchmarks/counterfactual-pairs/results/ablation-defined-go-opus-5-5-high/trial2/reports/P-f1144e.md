# Plan Review

**Requirement:** The report must cover each of the four supplied sources exactly once, and its coverage set must equal the supplied inventory.

**What the plan does:** It builds the report by iterating over the **full inventory**, producing one section per source.

## Analysis

1. **Coverage matches the inventory.** Because the plan iterates over the full inventory rather than the diff, every source gets a section, including the two or three that typically don't change. The checker's set-equality test is met by construction.

2. **Each source appears exactly once.** One section per inventory entry gives one-to-one coverage, assuming the inventory contains four distinct entries, as stated.

3. **It avoids the likely trap.** Since a typical diff touches only one or two sources, a diff-driven loop would miss sources. The checker would reject that report, and it would be marked INCOMPLETE and never recommended for readiness. Iterating over the inventory sidesteps this entirely.

4. **Per-section content is well defined.** SHA-256 and line count can be computed for any source, whether or not it changed. Including them for unchanged sources also gives useful evidence that those sources were actually examined.

## Optional hardening (not required)

- Before emitting the report, check that the generated section set equals the inventory and that its size is 4. This catches inventory or loop bugs early.
- Use a stable section order, such as inventory order, so reports diff cleanly between runs.
- Reject or deduplicate the inventory if it ever contains duplicate entries.

These only make a working plan more robust. The plan as written satisfies its stated rules and will pass the checker.
