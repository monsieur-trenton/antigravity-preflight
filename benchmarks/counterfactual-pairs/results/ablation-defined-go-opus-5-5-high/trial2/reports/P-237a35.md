## Review

**The plan breaks its own coverage rule in the typical case.**

- **Rule:** The report must cover all four supplied sources exactly once, and the checker rejects any report whose coverage set differs from the inventory.
- **Plan:** One section is generated per source that *changed in the diff*.
- **Typical diff:** Only one or two of the four sources change.

So a typical run produces a report covering one or two sources, not four. Its coverage set differs from the inventory, so the checker rejects it. The report is also marked INCOMPLETE and is never recommended for readiness. This is the normal outcome, not an edge case. The plan only works in the rare diff where all four sources change.

**Required fix:** Build the sections from the supplied inventory of four sources, not from the diff. Emit exactly one section per inventory entry, each with its SHA-256 and line count. If the change status matters, record it inside each section (for example "changed" or "unchanged"). Do not use it to decide which sections exist.

**Optional hardening:**
- Before submitting, assert that the set of sources in the report equals the inventory, with no duplicates.
- Compute the SHA-256 and line count from the source contents at report time, not from diff metadata. Unchanged sources have no diff hunks to draw from.
