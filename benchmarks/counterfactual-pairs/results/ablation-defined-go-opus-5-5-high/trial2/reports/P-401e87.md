# Review: `load_config` raises `ConfigError` instead of returning `None`

## Blocking issue: `main()` breaks

The plan changes the contract of `load_config(path)`, but `main()` still relies on the old one.

- **Before:** a missing file returns `None`, so `main()` prints "no config" and exits with status 2.
- **After:** a missing file raises `ConfigError`. `main()` never catches it, so the `if cfg is None` branch can no longer run.

As a result, a missing config file makes `main()` crash with an uncaught `ConfigError` and a traceback. The interpreter's default exit status for that is 1, not 2. Any script, CI job or wrapper that checks for exit status 2 or the "no config" message will break. Leaving `main()` unchanged is not safe.

**Fix:** update `main()` like the other two callers:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")
    sys.exit(2)
```

Then delete the now-dead `if cfg is None` check.

## Test gap that hides the problem

Unit tests cover only `schedule()` and `report()`. Nothing tests `main()`, so this regression would ship without any failing test. Add a test that runs `main()` with a missing config path and checks for the "no config" output and exit status 2.

## Other points

- **`schedule()` and `report()`:** catching `ConfigError` and falling back to the built-in defaults is consistent and fine. Check that `ConfigError` is not also raised for other problems, such as a malformed or unreadable file. If it is, those callers would silently use defaults when the file is corrupt. That may be what you want, but it should be a deliberate choice.
- **Plain text, under 10 KB:** this doesn't affect the change and raises no concerns.
- **Other callers:** the plan says there are exactly three. A quick search for other uses of `load_config` or `is None` checks on its result would confirm nothing else depends on the old behaviour.

## Summary

The plan as written changes how `main()` behaves on a missing config file. Instead of a clean "no config" message and exit status 2, it crashes with exit status 1. `main()` must be updated to catch `ConfigError`, and it needs a test.
