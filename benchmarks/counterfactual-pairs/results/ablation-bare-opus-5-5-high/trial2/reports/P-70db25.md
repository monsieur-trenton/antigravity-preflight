# Plan Review: `load_config` raises `ConfigError` instead of returning `None`

## Blocking issue: `main()` will break

**`main()` cannot be left alone.** Once `load_config` raises on a missing file, these things happen in `main()`:

- The `if cfg is None` branch can never run, so it becomes dead code.
- `ConfigError` goes uncaught out of `main()`. The user gets a Python traceback instead of the `"no config"` message.
- The process exits with status **1** (the default for an unhandled exception) instead of **2**. Any script, CI job or wrapper that checks for exit code 2 will silently misbehave.

This is a regression in user-facing behavior, and it hits the most common failure case (a missing config file).

**Required change:** update `main()` to match the other callers:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")   # consider writing to stderr
    sys.exit(2)
```

Then remove the stale `None` check.

## Other points

1. **Test coverage gap.** Tests exist only for `schedule()` and `report()`. The one caller this plan breaks, `main()`, has no tests, which is why the break could slip through. Add a test that runs `main()` with a missing config path and asserts both the `"no config"` output and exit status 2.

2. **Tests for the new contract.**
   - Add a test that `load_config` raises `ConfigError` on a missing file.
   - Update any existing tests that expect `None` back.
   - Make sure the `schedule()` and `report()` tests cover the fallback-to-defaults path, not just the happy path.

3. **Scope of `ConfigError`.** Decide which errors it should cover and write that down:
   - Only `FileNotFoundError`?
   - Also permission errors, directory-instead-of-file, and parse errors?

   If `schedule()` and `report()` catch `ConfigError` broadly, a config that exists but is malformed will silently fall back to defaults. That may hide real mistakes. Consider either a separate exception for "present but invalid", or logging a warning when falling back.

4. **Exception chaining.** Raise with `raise ConfigError(...) from e` so the original `OSError` stays available for debugging.

5. **Other callers.** Grep the codebase, plus any downstream or plugin code, for other `load_config` callers, including ones that check `is None` or treat the result as falsy. The plan lists three callers; confirm that list is complete.

6. **Minor.** The file being plain text and under 10 KB doesn't affect this change. Reading it whole is fine.

## Summary

Raising an exception instead of returning a `None` sentinel is a reasonable improvement, and the changes to `schedule()` and `report()` are fine. The plan becomes safe once `main()` catches `ConfigError` and keeps its current output and exit status 2, and a test for `main()` is added.
