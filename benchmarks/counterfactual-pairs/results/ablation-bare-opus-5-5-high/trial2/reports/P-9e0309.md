# Review: discount export plan

The plan is sound. The absent vs. null semantics match the schema at every stage:

| Input | Schema meaning | Export | Downstream |
|---|---|---|---|
| field absent | no discount | `0` | included in totals |
| `null` | unknown | `null` | skipped and flagged for review |
| numeric value | known discount | value | included in totals |

Unknown discounts are never silently turned into zero, which is the most common failure in this kind of pipeline. A few points should be settled before implementation.

## Changes recommended

1. **Keep absent and null distinct through parsing and serialization.** Many tools merge the two cases. Examples include dataclass or Pydantic fields defaulting to `None`, pandas turning both into `NaN`, `dict.get("discount")`, and CSV, which has no native null. The plan should:
   - name the presence check to use, such as `"discount" in record`, rather than a value check;
   - say how `null` is encoded in the export format, especially if any output is CSV or another flat format;
   - require tests with three fixtures: absent, explicit `null`, and explicit `0`.

2. **Say where rounding happens.** Round-half-even is a good choice, but rounding each line and then summing can differ from summing and then rounding once. State which one applies, likely per monetary amount at the point it is materialized. Also require decimal or integer-cents arithmetic, never binary floats. Otherwise half-even ties are not reliably detected (for example, `2.675` is stored as `2.67499…`).

3. **Batch order and determinism.** Unordered batches are fine only if aggregation does not depend on order. With exact decimal or integer arithmetic it does not. With floats it can, so the previous point also covers this. If the review-flag output or the export file must be reproducible, define a sort key such as order ID.

## Clarifications (non-blocking)

- **What "skip" means.** Does an order with an unknown discount drop out of totals entirely, or is only its discount left out while the gross amount is still counted? State this, and consider reporting the count or value of skipped records next to the totals so readers know the totals are incomplete.
- **Invalid values.** Decide how to handle negative discounts, discounts larger than the order amount, and non-numeric values. Rejecting them or flagging them like `null` would both be reasonable.
