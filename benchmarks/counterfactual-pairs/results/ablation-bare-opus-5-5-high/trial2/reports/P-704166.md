## Review

**The core arithmetic doesn't work for the observed data.**

The harness caps stdout at 1500 bytes. Let's size the worst case actually seen in testing:

- Three values at ~700 bytes each = ~2100 bytes — already over 1500 **before** counting anything else.
- Plus the other 3 values, plus JSON structural overhead: 6 keys (≤12B each = 72B), 6 pairs of key quotes (12B), 6 value quotes pairs (12B), 6 colons, 5 commas, 2 braces ≈ ~110 bytes of framing.

So the documented test case produces an encoded payload well above the cap. This isn't a rare edge; it's a case you already hit.

**What the assertion does and doesn't do.**

The pre-write assertion (`encoded length ≤ 1500`) is good hygiene — it guarantees you never *silently* breach the harness contract or get truncated mid-JSON. But it does not make the design safe. When the payload is 2100 bytes, the assertion fails, and per the contract that failure **aborts the release with no retry**. You've converted a truncation bug into a hard release-blocking failure. Same outcome for the business: no release.

**ASCII-escaping makes it worse, not better.** "About 700 bytes each" — if that's the *source* size, escaping non-ASCII/control bytes expands them (`\uXXXX` = 6 bytes per char, `\"`/`\\`/`\n` = 2 bytes). So encoded length can exceed the raw figure. If 700 is already the encoded size, the total still blows the cap.

**The fix is already half-present.** You have a debug log (temp file, outside the cap) — but it's deleted on exit, so it's useless for post-mortem on an aborted release. Recommended changes:

1. **Keep full values off stdout.** Put the complete summary (all 6 full values) in the debug log / an artifact file, not stdout.
2. **Emit a bounded summary to stdout**: fixed keys with elided/truncated values plus lengths and a hash/pointer (e.g. `"k":"<920B,sha=…>"`), sized to a conservative budget (~1200B to leave headroom).
3. **Persist the debug log** (don't delete on exit, or copy it to a durable artifact path) so the full data survives for diagnosis.
4. **Make the assertion non-fatal for the release**: if it would exceed the cap, auto-elide to the bounded form rather than aborting.

Without these, the design reliably aborts releases on exactly the kind of summary you already produced.
