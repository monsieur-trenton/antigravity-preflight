# Plan Review: Order Export, `discount` Handling

## Blocking issue: explicit `null` is collapsed into `0`

The schema defines three distinct states for `discount`:

| Source state | Schema meaning | Export writes | Downstream sees |
|---|---|---|---|
| absent | no discount | `0` | `0`, totaled normally ✅ |
| explicit `null` | discount **unknown** | `0` | `0`, totaled normally ❌ |
| number | known discount | value | value ✅ |

Writing `null` as `0` turns "unknown" into "known to be zero." This causes two problems:

1. **Downstream review never triggers.** Downstream totals skip and flag records whose discount is `null`. After this export, no record will ever be `null`, so the review path does nothing.
2. **Totals are silently wrong.** Records with unknown discounts get counted as full-price sales, which can overstate revenue. Nothing signals the error, and the export output cannot be used to recover the original information.

**Required change:** Keep the distinction.
- Absent → `0`. This is fine because the schema says absent means no discount.
- Explicit `null` → `null`, written in whatever form downstream recognizes as null.
- Add tests for all three cases: absent, `null`, and a numeric value such as `0` or `12.50`. Include an end-to-end check that a `null` record reaches downstream and gets flagged.

Check that the parser can tell absent from `null`. Many JSON and ORM layers merge them on read (for example, `record.get("discount")` returns `None` for both). Use a key-presence check before reading the value.

## Minor points

- **Rounding:** Round-half-even is a sound choice for money. Specify *where* rounding happens (per line vs. on aggregates) and confirm downstream uses the same mode. A mismatch causes cent-level drift between the export and the totals. Use decimal types, not binary floats, for the values being rounded.
- **Unordered batches of 500:** This is fine if each record's output depends only on that record. Confirm two things:
  - Retries of a failed batch are idempotent, so they don't duplicate or drop records.
  - Any consumer or diff tool that compares exports does not assume a stable order. If it does, sort by a stable key such as order ID at write time.

## Summary

The batching and rounding are reasonable. The `null` → `0` mapping contradicts the schema and disables the downstream safeguard for unknown discounts. It must be fixed before shipping. The fix is small and well-scoped.
