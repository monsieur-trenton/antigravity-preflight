# Review: `load_config` raises `ConfigError` instead of returning `None`

The overall direction is sound. Raising on a missing file is clearer than returning `None`, and the plan keeps the existing behaviour at each call site. A few gaps need closing first.

## What's good
- **All three named callers get explicit handling.** None of them is left to crash on a new exception.
- **`main()` keeps its contract.** It still prints "no config" and exits with status 2.
- **The fallback in `schedule()` and `report()` is explicit**, not an accidental `None` passed further down.

## Required changes

1. **Test `main()`.** The entry point is where the user-visible contract lives: the message, exit code 2 and the stream it prints to. It's the only caller whose behaviour must match the old behaviour exactly, and it has no tests. Add a test that a missing file produces exit status 2 and "no config". Use `pytest.raises(SystemExit)` or a subprocess test.

2. **Confirm the caller list.** "Its callers are schedule(), report() and main()" should come from a search, not from memory. Grep the codebase, plugins, scripts and any downstream packages for `load_config` and for code that checks its result with `is None` or `if not cfg`. Anything missed will now crash with an unhandled `ConfigError` instead of handling `None`.

3. **Update existing tests and mocks.** Any test that asserts `load_config(...) is None`, or mocks it with `return_value=None`, will now give false results. Switch these to `side_effect=ConfigError(...)`. Add a direct unit test of `load_config` itself, checking that a missing path raises `ConfigError`.

4. **Define what `ConfigError` covers.** The plan only mentions a missing file. Decide and document what happens with:
   - permission denied
   - a directory instead of a file
   - undecodable content, given that files are "plain text"
   - malformed content

   If these raise other exceptions, `schedule()` and `report()` will still crash in those cases. That may be fine, but it should be a deliberate choice. If `ConfigError` is broadened to cover them, make sure the silent fallback to defaults is really wanted for a corrupt file, not just a missing one.

## Suggestions

- **Log the fallback.** When `schedule()` or `report()` fall back to defaults, log at debug or info level. Otherwise a mistyped path silently runs with defaults and is hard to diagnose.
- **Check how `main()` relates to `schedule()` and `report()`.** If `main()` calls them rather than calling `load_config` directly, their fallback will absorb the error, and `main()`'s "no config" exit may never trigger. Make sure `main()` checks for the config before handing off, or the exit-2 behaviour is silently lost.
- **Preserve the original cause.** Use `raise ConfigError(...) from e` when wrapping `FileNotFoundError`.
- **The 10 KB / plain-text note doesn't affect this change.** Either remove it, or enforce it, for example by rejecting files over the limit with `ConfigError`.
