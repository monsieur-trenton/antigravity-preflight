# Review: `load_config` raising `ConfigError` for missing files

## Blocking issue: `main()` breaks

The plan leaves `main()` unchanged, but `main()` depends on the old contract:

```python
cfg = load_config(path)
if cfg is None:          # no longer reached for a missing file
    print("no config")
    sys.exit(2)
```

With the new behavior, a missing file raises `ConfigError` before the `None` check runs. That causes two problems:

- **Behavior regression.** Instead of printing "no config" and exiting with status 2, the program crashes with an uncaught traceback and exits with status 1. Any script, CI job or wrapper that checks for exit code 2 will now misbehave.
- **Dead code.** The `is None` branch can no longer fire for a missing file. It is misleading if `load_config` never returns `None` now.

**Fix:** update `main()` to catch the exception and keep the old outward behavior.

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")
    sys.exit(2)
```

Remove the `is None` check if `load_config` can no longer return `None` at all.

## Test gap

Tests cover only `schedule()` and `report()`, so the regression above would ship undetected. Add a test for `main()` with a missing config path that asserts:
- "no config" is printed
- the exit status is 2

## Points to clarify

1. **Full return contract.** Is a missing file the only case that used to return `None`? If `load_config` still returns `None` in other cases (such as an empty file), state that. Every caller then needs to handle both `None` and the exception.
2. **Scope of `ConfigError`.** Does it also cover unreadable files and parse errors, or only missing files? If it covers all of them, `schedule()` and `report()` will silently fall back to defaults on a malformed config. That could hide real user mistakes. Consider falling back only on "missing", or at least logging a warning when falling back.
3. **Other callers.** Confirm by search, not memory, that these three are the only call sites, including scripts, tooling and tests that call `load_config` directly.

## Fine as is

- Catching the error and falling back to defaults in `schedule()` and `report()` is reasonable, given the logging caveat above.
- The file size and format (plain text, under 10 KB) don't affect this change.

## Summary

The core change is sound. However, the plan explicitly leaves one caller relying on the old `None` contract, and that caller is untested. Updating `main()` and adding a test for it is small and well understood.

VERDICT: GO_WITH_CHANGES
