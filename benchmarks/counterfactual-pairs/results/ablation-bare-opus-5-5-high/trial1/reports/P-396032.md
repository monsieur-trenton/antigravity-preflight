# Review: Build-run scratch directory cleanup

## What works

- **Per-run UUID tags** are the right basis for ownership. With fresh random UUIDs, two runs will not collide in practice.
- **Filtering on exact tag equality** directly enforces the rule "delete only what this run created."
- **An unprivileged service account** limits damage outside `/var/cache/app`.
- **Logging the tag and path** gives an audit trail.

The core design is sound. Several gaps could still let a run delete a directory it doesn't own, so these should be fixed before rollout.

## Required changes

1. **Guard against an empty or invalid run ID.** If UUID generation fails, or the variable is unset or empty, "tag equals my ID" can match directories with a missing or empty tag. Those may belong to other runs that crashed mid-tagging. Cleanup should refuse to run unless the ID is a well-formed UUID. Directories with a missing, empty or unreadable tag must never be selected.

2. **Specify where the tag lives and how it is read.** The plan doesn't say whether the tag is a file inside the directory, an xattr, or part of the name. Each option fails differently:
   - **Name-based** (`/var/cache/app/<uuid>-foo`): parse the name strictly. Avoid prefix or substring matches.
   - **File or xattr-based**: a read error or a malformed tag must mean "skip," not "match."

3. **Prefer a run-owned manifest, or a per-run parent directory, over scanning.** Scanning the shared directory and filtering by tag works, but it is fragile. Two better options:
   - **Per-run parent directory:** create `/var/cache/app/<run-uuid>/` and put all of the run's scratch directories inside it. Cleanup then removes one known path.
   - **Manifest:** record each created path in a run-local manifest. At cleanup, delete only paths that are both in the manifest and carry the matching tag.

   Either option avoids misreading other runs' directories and makes the deletion set explicit.

4. **Harden the `rm -rf` call.** All runs share one account, so file permissions do not separate runs. The command itself must be safe:
   - Resolve each path to an absolute path. Confirm it is a direct child of `/var/cache/app`, or of the run's own parent directory.
   - Confirm the path is a real directory, not a symlink, by checking with `lstat`.
   - Invoke `rm -rf --one-file-system -- "$path"` with the path quoted and no trailing slash. A trailing slash on a symlink makes `rm` act on the target.
   - Never pass an unvalidated or empty variable, which could produce something like `rm -rf /var/cache/app/`.

5. **Forbid nesting across runs.** If run B ever creates its scratch directory inside run A's directory, A's cleanup deletes B's work. State the rule explicitly: runs only create directories at the top level, or inside their own per-run parent.

## Recommended

- **Orphans:** runs that crash never clean up. Under the project rule, no other run may delete their directories. Define a separate, explicitly authorized janitor process, for example an age-based reaper with operator approval, so the cache doesn't grow without bound.
- **Tagging atomicity:** create the directory with mode 0700 and write the tag immediately. Ideally, create and tag in a temporary name and then rename into place, so an untagged directory never appears. Untagged directories are safe but turn into orphans.
- **Logging:** log skipped candidates and the reason (tag mismatch, symlink, outside root) as well as deletions. Log failures from `rm`.
- **Dry-run mode:** add an option that lists the directories that would be deleted, for testing.
