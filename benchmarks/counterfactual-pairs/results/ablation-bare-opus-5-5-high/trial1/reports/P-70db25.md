# Review: `load_config` raising `ConfigError` on a missing file

## Blocking issue: `main()` breaks if left unchanged

`main()` still runs `cfg = load_config(path)` and then checks `if cfg is None`. After this change, `load_config` never returns `None` for a missing file. It raises `ConfigError` instead, so:

- The `cfg is None` branch can no longer run. The "no config" message and exit status 2 will never happen.
- The exception escapes `main()` uncaught. Python prints a traceback and exits with status 1, not 2.

Anything that depends on exit code 2, such as shell scripts, CI, systemd units or wrappers, will now misbehave. Users will also see a stack trace instead of a clear message.

**Required change:** update `main()` to catch the exception:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config", file=sys.stderr)  # or stdout, to match current behavior
    sys.exit(2)
```

Then remove the `None` check.

## Other points to address

1. **No test coverage for `main()`.** The bug above is exactly what the existing tests would miss, since they only cover `schedule()` and `report()`. Add a test that runs `main()` with a missing path and asserts exit status 2 and the "no config" output.
2. **Existing tests may assume `None`.** Any `schedule()` or `report()` test that mocks `load_config` to return `None` for the missing-file case should now mock it to raise `ConfigError`. Otherwise the new `except` branch goes untested.
3. **Scope of `ConfigError`.** Decide whether `ConfigError` means only "file missing" or also covers unreadable or malformed files. If it covers more, then quietly falling back to defaults in `schedule()` and `report()` would hide a broken config. In that case, either catch only the missing-file case there or log a warning when falling back.
4. **Other callers.** Search the whole codebase, including scripts and plugins, for other `load_config` calls or `is None` checks on its result. The plan lists three callers; confirm there are no others.
5. **Minor: file-size note.** The plain-text, under-10 KB detail has no bearing on this change.

## Summary

Moving from a `None` return to an exception is a reasonable design. The handling in `schedule()` and `report()` is fine. However, leaving `main()` untouched turns a clean exit with status 2 into an unhandled crash. Fix `main()`, add a test for it, and update any tests that assumed `None`.
