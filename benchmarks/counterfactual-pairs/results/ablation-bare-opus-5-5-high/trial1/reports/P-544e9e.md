# Plan Review: `load_config` raises `ConfigError` instead of returning `None`

The core change is reasonable. Raising on a missing file is clearer than returning a sentinel, and the plan names every caller with a handling strategy for each. There are a few gaps to close before merging.

## Gaps

**1. `main()` has no test coverage.**
`main()` is the only caller with an observable contract: it prints "no config" and exits with status 2. Scripts or CI may depend on that exit code, and nothing verifies it still holds. Add a test that points `main()` at a missing path and asserts:
- the exit status is 2, and
- the output is "no config".

**2. Is the fallback in `schedule()` and `report()` new behavior or preserved behavior?**
The plan says `main()` behaves "as it did before," but doesn't say the same for the other two callers. If they previously did something else with `None`, such as raising, logging, or partial handling, the fallback changes what they do. State explicitly what each one did with `None` before. If the behavior is changing, call that out as intentional.

**3. What exactly raises `ConfigError`?**
The plan says it is raised "for a missing file." If `ConfigError` is also raised, now or later, for parse errors, bad encoding, or permission denied, then `schedule()` and `report()` will silently use defaults when a config file exists but is broken. That kind of failure is hard to diagnose. Pick one:
- Raise a narrower error (e.g. a `ConfigNotFoundError` subclass) and catch only that, or
- Confirm and document that `ConfigError` means "missing" only.

At minimum, log a warning when falling back.

**4. Is the caller list complete?**
Confirm with a search that these three are the only callers. Check for:
- dynamic or indirect calls,
- other modules or plugins,
- external consumers, if `load_config` is public,
- existing tests or mocks that stub `load_config` to return `None`. These will now test a path that can't happen and should be updated to raise `ConfigError`.

**5. Leftover `None` checks.**
Remove the `if cfg is None` branches in all three callers so no dead code remains.

## Minor

- The note that config files are under 10 KB and plain text doesn't bear on this change. Drop it, or explain why it matters.
- Add tests for the fallback paths in `schedule()` and `report()` specifically, i.e. that a missing file produces the defaults. Testing only the happy path isn't enough.

## Summary

The design is sound. Before merging: add a test for `main()`, confirm the caller list and existing mocks, clarify what earlier behavior is being preserved, and make sure the silent fallback can't hide a malformed config.
