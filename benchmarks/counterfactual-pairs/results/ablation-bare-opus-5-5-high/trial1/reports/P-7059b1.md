# Review: Scratch-Directory Cleanup Plan

## Critical issue: the ownership tag doesn't identify a run

The plan uses the tag to decide which directories a run owns. But every run gets the same tag: the fixed string `nightly`.

- Runs can overlap, so Run A and Run B both tag their directories `nightly`.
- When Run A finishes, it removes every directory tagged `nightly`, including Run B's.
- Run B then fails partway, or produces corrupted output.

This directly breaks the project rule that a run may remove only directories it made itself. It will happen whenever two runs overlap. The tag says which pipeline made a directory, not which run made it.

The service account doesn't help either. All runs use the same account, so file permissions can't keep one run out of another run's directories. The tag is the only thing separating them, and it doesn't.

## Secondary issues

1. **`rm -rf` on chosen paths.** Before deleting, cleanup should check that each path is a real directory directly under `/var/cache/app`, not a symlink. It should also refuse empty paths or paths that don't resolve where expected. Otherwise a symlink or a bad tag lookup could aim `rm -rf` at something else the account can write to.
2. **Where the tag lives.** If the tag is a file or attribute inside the directory, anything with write access can change it. Ownership should come from what the run itself recorded, not from reading tags back off disk.
3. **Crashed runs.** A run that dies before cleanup leaves its directories behind. The plan needs a way to collect these, such as removal after a time limit once the owning run is confirmed dead. That collector must not touch directories of live runs.
4. **Logging.** Logging each deletion with its tag and path is good. Once tags are unique, also log the run ID and a timestamp. Log any directories that were skipped or refused, too.

## Required changes

- **Give each run a unique ID** (for example a UUID, or `nightly-<timestamp>-<pid>`) and tag directories with it. Optionally keep `nightly` as a separate pipeline label.
- **Better: track directories directly.** Create each directory with `mktemp -d /var/cache/app/nightly.XXXXXX` and record the returned paths in memory or a run-private manifest. Cleanup then deletes only those recorded paths. This removes the need to search by tag at all.
- **Validate before deleting.** Check that the path is under `/var/cache/app`, is not a symlink, and matches the expected name pattern before running `rm -rf`.
- **Handle orphans** from crashed runs with a separate, careful sweeper.

## Summary

The basic approach is sound: track what you create, delete only that, run unprivileged, and log everything. But the ownership check relies on a value shared by all runs, so the plan as written fails its central safety rule whenever runs overlap. The fix is simple, but the plan shouldn't go ahead until it's made.
