# Review

**The plan should not ship as written.** The export erases the "unknown discount" state, so downstream review never sees the records it is supposed to flag.

## Blocking issue: null discounts are silently converted to 0

The schema gives `discount` three distinct meanings:

| Source value | Schema meaning | Export writes | Downstream behavior |
|---|---|---|---|
| absent | no discount | `0` | correct |
| `0` | zero discount | `0` | correct |
| `null` | **unknown** | `0` ❌ | should skip and flag, but sees `0` and includes it |

The consequences:

1. **The review path is dead.** Downstream only flags records whose discount is null. Since the export never emits null, nothing is ever flagged.
2. **Totals are silently wrong.** Records with unknown discounts are counted as full-price, which may overstate revenue. Nothing indicates this happened.
3. **The damage can't be undone downstream.** Once null becomes 0 in the export, no consumer can recover the distinction.

**Required change:** Keep the distinction through the export.
- absent → `0` (or absent, if downstream treats both as zero)
- `null` → `null`

Add a test fixture with all three cases (absent, explicit `0`, explicit `null`). Assert that only the `null` record is skipped from totals and flagged.

## Non-blocking notes

- **Rounding (round-half-even):** This is a reasonable choice, but the plan should say *where* rounding happens: per line, per record, or on the final total. Rounding at different stages gives different totals. Also confirm downstream uses the same mode, or totals won't reconcile. Use decimal types, not floats, so the half-even tie rule applies to real ties.
- **Unordered batches of 500:** This is fine as long as aggregation is order-independent. With per-record rounding before summing, it is. Two things to state explicitly:
  - The output must not rely on record order.
  - Retrying or partially failing a batch must not double-count or drop records. The export should be idempotent, keyed by order ID.
- **Observability:** Log a count of null-discount records per run. A sudden drop to zero would have caught this bug.

## Path to GO

Preserve `null` through the export, add the three-case test, and specify where rounding happens. With those changes, the plan is sound.
