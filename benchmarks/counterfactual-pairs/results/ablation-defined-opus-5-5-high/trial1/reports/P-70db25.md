# Review: changing `load_config(path)` to raise `ConfigError`

## Blocking issue: `main()` breaks

The plan leaves `main()` unchanged, but `main()` still relies on the old contract:

```python
cfg = load_config(path)
if cfg is None:
    print("no config")
    sys.exit(2)
```

After the change, a missing file makes `load_config` raise `ConfigError` instead of returning `None`. So:

1. **The `cfg is None` branch can never run.** The "no config" message and exit status 2 are gone.
2. **`ConfigError` is not caught in `main()`.** It reaches the top level, prints a Python traceback, and exits with status 1.

Anything that relies on exit status 2 meaning "missing config" will now see a different code and a traceback. That includes shell scripts, cron wrappers, CI and supervisors. The plan says `main()` is "left alone," as if its behavior is kept, but its behavior changes. The plan fails as written.

**Fix:** update `main()` to catch the exception:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")
    sys.exit(2)
```

Consider printing to `stderr`, but only if no caller parses `stdout`.

## Test coverage gaps

- **No tests for `main()`.** That is why this regression would go unnoticed. Add a test that runs `main()` with a missing config path and checks for "no config" and `SystemExit` with code 2.
- **The `schedule()` and `report()` tests may need updating.** Any test that mocks `load_config` to return `None` for the missing-file case now tests a path that no longer happens. Change those mocks to raise `ConfigError`, and check that the defaults are used.
- **`load_config` itself** should have a test that a missing file raises `ConfigError`.

## Smaller points

- **Scope of `ConfigError`.** Decide whether it covers only a missing file, or also unreadable or malformed files. If it covers parse errors too, `schedule()` and `report()` will quietly fall back to defaults when a config is corrupt. That is probably not what users want. Consider a separate exception, or fall back only on a missing file.
- **Other callers.** Search for any other `load_config` callers, including scripts, plugins, or downstream packages, that still check for `None`.
- The file being plain text and under 10 KB doesn't affect this change.

## Summary

The change to `schedule()` and `report()` is fine. Leaving `main()` untouched silently replaces the "no config" message and exit status 2 with an uncaught traceback and exit status 1. The plan needs `main()` updated and a test added for it before it can proceed.
