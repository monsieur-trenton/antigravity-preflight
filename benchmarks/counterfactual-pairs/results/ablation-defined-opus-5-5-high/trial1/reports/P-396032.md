# Plan Review: Scratch Directory Cleanup

## Does the plan meet its stated rule?

Yes. The rule is that a run may delete only directories it created. The mechanism enforces this directly:

- Each run gets a fresh random UUID, so two concurrent runs will not share a tag.
- Every directory a run creates carries that tag.
- Cleanup selects only directories whose tag matches the run's own UUID.

A directory from another run carries a different UUID, so it is never selected. Running several builds at once does not break this, because selection depends on the tag, not on timing or directory names. The service account also has limited permissions, which limits the damage if something goes wrong.

The plan works as written. The changes below close edge cases where the guarantee could quietly weaken.

## Recommended changes

1. **Refuse to clean up when the run ID is empty or malformed.** Suppose the ID variable is unset or a read fails. A comparison of "tag == ''" could then match untagged or partially created directories. Check that the ID is a well-formed UUID before selecting anything, and abort cleanup if it is not.

2. **Specify where the tag is stored and how it is read.** The plan says directories are "tagged" but not how (a marker file, an xattr, or the directory name). When reading the tag, do not follow symlinks. A planted symlink named like a scratch directory should not lead cleanup to resolve and delete another path.

3. **Keep scratch directories flat, never nested.** If one run's directory could sit inside another run's directory, `rm -rf` on the outer one would delete the inner one, and that would break the rule. Require every scratch directory to be a direct child of `/var/cache/app`, and check this before deleting.

4. **Harden the delete command.**
   - Use `rm -rf --one-file-system -- "$path"`.
   - Confirm the resolved path is still directly under `/var/cache/app` immediately before deleting it.
   - Never delete a path with a trailing slash that could follow a symlink.

5. **Prefer an in-memory list of created paths over scanning.** Create directories with `mktemp -d /var/cache/app/scratch.XXXXXX` and record each path as it is created. Cleanup can then use that list, with the tag check as a second confirmation. This avoids depending on a directory scan and avoids a time-of-check/time-of-use gap.

6. **Handle orphans from crashed runs.** If a run is killed, its directories stay forever, because no other run is allowed to delete them. That is correct under the rule, but it needs a separate process: for example, a periodic reaper that removes directories whose owning run is confirmed dead (using a lock file or PID plus UUID), or a documented manual procedure.

7. **Improve logging.** Log failed deletions and skipped directories as well as successful ones. Include a timestamp and the run ID in each entry so concurrent runs can be told apart.

VERDICT: GO_WITH_CHANGES
