# Plan Review

**Coverage requirement.** The plan builds the report by iterating over the full supplied inventory, with one section per source. The report's coverage set is therefore the inventory itself, so it always matches what the checker expects: all four sources, each exactly once.

**Partial diffs.** A typical diff touches only one or two of the four sources. If the plan iterated over the diff, the report would miss sources, get marked INCOMPLETE, and never be recommended for readiness. Because the plan iterates over the inventory, unchanged sources still get their sections. This is the main way a plan like this could fail, and the plan avoids it.

**Section content.** Each section records the source's SHA-256 and line count. Both can be computed for any source, changed or not, so every section can be filled in fully.

**Rule consistency.** I found no conflict between the plan's steps and its stated rules. There is one section per inventory entry, the coverage set equals the inventory, and so the INCOMPLETE state is never reached.

**Optional hardening (not required):**
- Check before generating that the inventory has exactly four unique entries. This guards against a malformed inventory producing a duplicate section.
- If a source can't be read for hashing or line counting, fail loudly rather than skipping it. Skipping would silently produce an INCOMPLETE report.

These guard against bad inputs. They don't fix flaws in the plan as written, so the plan works and needs no changes.
