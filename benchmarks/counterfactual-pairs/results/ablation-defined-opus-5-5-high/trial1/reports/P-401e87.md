# Plan Review: `load_config` Raising `ConfigError`

## Blocking issue: `main()` breaks

The plan leaves `main()` unchanged, but `main()` depends on the behavior being removed.

- **Before:** a missing file makes `load_config(path)` return `None`. `main()` sees `cfg is None`, prints "no config" and exits with status 2.
- **After:** a missing file makes `load_config(path)` raise `ConfigError`. `main()` never catches it, so the `if cfg is None` check never runs. In Python, an uncaught exception prints a traceback and exits with status **1**, not 2.

So the documented behavior of `main()` ("no config", exit 2) silently stops happening. Anything that checks for exit code 2 will misread the failure. That includes shell scripts, CI jobs, systemd units and wrappers. Users will also see a traceback instead of a clean message.

Nothing will catch this before release. Tests cover only `schedule()` and `report()`, and `main()` has no test.

## Required changes

1. **Update `main()`** to handle the new contract:
   ```python
   try:
       cfg = load_config(path)
   except ConfigError:
       print("no config")
       sys.exit(2)
   ```
   Remove the `if cfg is None` check, unless `load_config` can still return `None` in some other case (see item 3).
2. **Add a test for `main()`**: point it at a missing file and assert that it prints "no config" and exits with status 2. Use `pytest.raises(SystemExit)` and check `.code == 2`, or run it as a subprocess.
3. **Pin down the full `load_config` contract.** Check whether it can still return `None` in any case, such as an empty file. Also decide whether other failures, like a permission error or bad syntax, raise `ConfigError` or something else. The callers' `except` clauses should match.
4. **Search for other callers.** Grep the codebase and any downstream users to confirm these three are really the only ones. Any caller that isn't listed and checks for `None` will break the same way `main()` does.

## Minor points

- In `schedule()` and `report()`, falling back to defaults silently can hide a mistyped path. Consider logging a warning when the fallback happens.
- The note that config files are plain text and under 10 KB has no bearing on this change.

## Summary

The changes to `schedule()` and `report()` are fine. Leaving `main()` unchanged breaks its stated behavior: it will crash with exit code 1 instead of printing "no config" and exiting with 2. The test plan has no coverage that would catch this.
