## Review

**Blocking issue: `main()` breaks.**

The plan changes `load_config(path)` so a missing file raises `ConfigError` instead of returning `None`, but it leaves `main()` alone. `main()` still does:

```python
cfg = load_config(path)
if cfg is None:
    print("no config")
    sys.exit(2)
```

After the change:
- `load_config` never returns `None` for a missing file, so the `if cfg is None` branch is dead code.
- The `ConfigError` goes uncaught out of `main()`. The process prints a traceback and exits with status **1**, not 2. It no longer prints "no config".

Anything that depends on that contract will break. That includes shell scripts, CI jobs, wrappers and users who check for exit code 2 or the "no config" message. So the plan, as written, causes a behavior regression at the entry point.

**Required fix:** update `main()` to catch the exception and keep the existing behavior:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")
    sys.exit(2)
```

Then remove the `is None` check, unless `load_config` can still return `None` for some other reason. If so, document that reason.

**Other gaps:**

1. **Test coverage misses the broken path.** The tests cover only `schedule()` and `report()`, which is why this regression would get through. Add a test for `main()` with a missing config file. It should assert exit status 2 and the "no config" output.
2. **Scope of `ConfigError`.** Say whether `ConfigError` is raised only for a missing file, or also for unreadable or malformed files. If it covers more, `schedule()` and `report()` will quietly fall back to defaults on a corrupt config. That could hide real errors. Consider catching only the missing-file case there, or logging a warning when falling back.
3. **Other callers.** Confirm there are no other callers of `load_config` that check for `None`, such as scripts, plugins or other modules. A quick grep before merging would settle this.
4. **Fallback consistency.** Make sure `schedule()` and `report()` use the same defaults source, so they can't drift apart.

The note that config files are plain text and under 10 KB doesn't affect this change.
