# Review: Scratch Directory Cleanup Plan

## Does the plan meet its rules?

Yes. The core mechanism is correct:

- **Ownership is unambiguous.** Each run gets a fresh random UUID, and cleanup deletes only directories whose tag exactly equals that UUID. Another run's directories carry a different UUID, so they are never selected.
- **Concurrency is handled.** Selection depends only on tag equality, not on timing, so concurrent runs cannot cross-select each other's directories.
- **Blast radius is limited.** The unprivileged account cannot reach anything outside its own permissions, even if a path is wrong.
- **Auditability is good.** Logging the tag and path for each deletion lets you check after the fact that only owned directories were removed.

Nothing here causes the plan to fail or break its rule. Some gaps are still worth closing.

## Recommended changes

1. **Guard against an empty or malformed identifier.** Before cleanup, check that the run ID is a well-formed, non-empty UUID. If ID generation or propagation ever breaks, "tag equals empty string" could match untagged or partially tagged directories from other runs. Abort cleanup if the check fails.

2. **Make tagging atomic with creation.** If the tag is written after `mkdir` (for example, as a marker file), a crash in between leaves an untagged directory. Put the UUID in the directory name instead (`mktemp -d /var/cache/app/build-<uuid>-XXXX`), so the tag exists the moment the directory does.

3. **Prefer a run-local manifest over scanning.** Record each created path in memory or a run-private file, then delete exactly those paths after confirming the tag. This avoids depending on a scan of a shared directory and removes ambiguity about where the tag is read from.

4. **Be careful with symlinks and scan scope.**
   - Only consider direct children of `/var/cache/app`.
   - Skip symlinks rather than following them.
   - Call `rm -rf -- "$path"` with no trailing slash, so a swapped-in symlink is removed as a link and its target is untouched.

   All runs share one service account, so a buggy run could in principle tamper with entries between selection and deletion.

5. **Handle orphans from crashed runs.** A run that dies never cleans up, and its directories stay forever. Add a separate janitor that removes directories older than a generous threshold, but only when it can confirm the owning run is no longer active (for example, with a heartbeat or lock file per run). That keeps the "never delete another run's directories" rule intact for live runs. Also run cleanup from a `trap`/`finally` so normal failures still clean up.

6. **Log failures too.** Record failed or partial `rm -rf` results with tag and path, not just successful deletions.

## Summary

The ownership model is correct and safe under concurrency. The improvements above cover defensive validation, atomic tagging, symlink and race hardening, and leftover directories from crashed runs.
