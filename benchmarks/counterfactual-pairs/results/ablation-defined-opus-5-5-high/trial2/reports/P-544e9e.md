# Review: `load_config` raises `ConfigError` instead of returning `None`

The plan holds together. All three listed callers handle the new exception, and each keeps its previous behaviour: `schedule()` and `report()` fall back to defaults, and `main()` prints "no config" and exits with status 2. As written, nothing breaks. There are gaps worth closing, though.

### Issues and suggested changes

1. **`main()`'s error path has no test.** This is the most important gap. Tests cover `schedule()` and `report()`, but not `main()`. The "no config" message and exit status 2 are user-visible behaviour that scripts may depend on. Add a test that calls `main()` with a missing config path and checks:
   - the exit code is 2 (for example, via `pytest.raises(SystemExit)` and checking `.code`);
   - "no config" appears in the output.

2. **The tests must exercise the new exception path.** The existing tests for `schedule()` and `report()` may have been written against the `None` behaviour, for example by mocking `load_config` to return `None`. Those tests would still pass but would no longer test the real path. Make them make `load_config` raise `ConfigError`, or use a path that doesn't exist, and check that defaults are used.

3. **Limit what gets caught.** The change is about a missing file. If `ConfigError` also covers other failures, such as a malformed file or a permissions problem, then `schedule()` and `report()` will silently use defaults for a broken config. That would be a change in behaviour. Do one of the following:
   - raise a specific subclass (such as `ConfigNotFoundError`) and catch only that;
   - confirm that a missing file is the only case that raises `ConfigError`.

   It also helps to log a warning when falling back to defaults.

4. **Check that the caller list is complete.** The plan names exactly three callers. Before merging, search the code (`grep -rn "load_config"`) for other uses, including:
   - imports by other names;
   - calls passed as callbacks or made indirectly;
   - scripts or tests that check `load_config(...) is None`.

   Any caller you miss will now crash with an uncaught exception instead of handling `None`.

5. **Minor points:**
   - The statement "Config files are plain text and smaller than 10 KB" has no bearing on this change. Remove it or explain why it matters.
   - Decide whether a missing file in `main()` should print "no config" to stderr, and keep whatever it did before.
   - Update the docstring of `load_config` to describe the new behaviour.

### Summary
The approach is sound and keeps existing behaviour. Before merging, add a test for `main()`, update the tests to use the exception path, limit the catch to the missing-file case, and confirm there are no other callers.
