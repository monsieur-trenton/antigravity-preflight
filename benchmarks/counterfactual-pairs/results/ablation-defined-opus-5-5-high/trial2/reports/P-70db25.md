## Review

**The problem: `main()` breaks**

Once `load_config(path)` raises `ConfigError` for a missing file, it never returns `None` in that case. `main()` is left unchanged, so:

- `cfg = load_config(path)` raises `ConfigError` before the `if cfg is None` check runs.
- The exception is not caught, so the program crashes with a traceback.
- Python then exits with status **1**, not **2**, and never prints `"no config"`.
- The `None` check in `main()` becomes dead code.

The plan says main() "prints 'no config' and exits with status 2," but with this change it will do neither. Any script, CI job or caller that checks for exit code 2 or that message will break. So the plan fails as written.

**Required fix**

Update `main()` to catch the exception:

```python
try:
    cfg = load_config(path)
except ConfigError:
    print("no config")
    sys.exit(2)
```

Then remove the old `if cfg is None` branch, unless `load_config` can still return `None` in other cases. If it can, document when.

**Other points**

1. **Testing gap.** Unit tests cover `schedule()` and `report()` but not `main()`. That is why this regression could get through. Add a test that runs `main()` with a missing config file and checks the `"no config"` output and exit status 2. Also add tests for the new `ConfigError` path in `schedule()` and `report()`, since the existing tests probably mock `None`. Check any mocks of `load_config` that return `None` for "missing", because they now describe behavior that no longer exists.
2. **Scope of `ConfigError`.** State whether `ConfigError` is raised only for a missing file, or also for permission errors, unreadable files or bad content. If `schedule()` and `report()` catch it broadly, a malformed config would quietly fall back to defaults. That may hide real mistakes. Consider separate subclasses, or only falling back to defaults when the file is missing.
3. **Other callers.** Search the codebase for any other `load_config` callers that check for `None`, such as scripts, plugins or tests. The plan names only three.
4. **Silent fallback.** Consider logging a warning when `schedule()` or `report()` uses the defaults, so a missing config is visible.
5. **File-size note.** "Plain text, <10 KB" doesn't affect this change. It's fine to keep, but it doesn't justify any design choice here.
