# Review

**Blocking issue: the export erases the distinction between "no discount" and "unknown discount."**

The plan states two rules that conflict with its own design:

1. **The schema rule:** an absent `discount` means *no discount*, and an explicit `null` means the discount is *unknown*. These are different meanings.
2. **The downstream rule:** totals skip records with a `null` discount and flag them for review.

The export writes both absent and `null` as `0`. This causes two failures:

- **Schema violation:** An unknown discount becomes a definite "no discount." That is the opposite of what the schema says `null` means.
- **Broken downstream behavior:** After export, no record has a `null` discount, so downstream never skips or flags anything. Records with unknown discounts go into the totals as if they had no discount. Totals may be overstated, and the review process never sees these records. Nothing reports the error.

**Required fix:**
- Absent `discount` → write `0` (correct per schema).
- Explicit `null` → write `null` (or an equivalent the downstream reader treats as null), so those records are still skipped and flagged.
- Add a test with three records: one absent, one `null`, and one with an explicit value. Check that the export output differs between the first two, and that downstream flags only the `null` record.

**Other points (non-blocking):**
- **Round-half-even to cents** is a reasonable choice for monetary values. Make sure rounding uses decimal arithmetic, not binary floats, so half-cent cases round as intended. Also confirm whether rounding happens per line or on totals, so downstream sums reconcile.
- **Unordered batches of 500** are fine if the export and totals are order-independent, which sums are. If any output relies on record order (sequence numbers, a "first/last" field, or deterministic file diffs), sort before writing or document that order is not guaranteed. Also confirm that a failed batch can be retried without double-counting.

The null-handling issue alone makes the plan fail against rules it states, so it can't go ahead as written.
