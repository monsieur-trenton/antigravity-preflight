# Plan Review: Snapshot S01

### Advisory Review & Rationale

**Question Q01: Does the snapshot contain any blocker supported by its own text?**
**Answer:** Yes. Snapshot S01 contains a critical blocker supported directly by internal contradictions within its own text.

#### Analysis of the Blocker
1. **Business Invariant:** Line `[S01:7]` defines a strict requirement: *"Rule: a customer must never be charged more than once for a single order."*
2. **Processor Idempotency Semantics:** Line `[S01:2]` specifies that within 24 hours, the processor treats repeated idempotency keys as the same request (returning the original result without charging again), whereas *"a new key always creates a new charge."*
3. **Timeout Uncertainty & Retry Policy:** Line `[S01:3]` explicitly acknowledges that a timed-out submission may already have been charged by the processor. Lines `[S01:4]` and `[S01:6]` specify that the worker retries timed-out submissions up to 3 more times even when the outcome is unknown.
4. **The Defect:** Line `[S01:5]` states: *"Each attempt, including every retry, generates a fresh random UUID and sends it as the idempotency key."*

Because every retry transmits a new UUID rather than retaining the original attempt's idempotency key, the processor will treat any retry following an accepted-but-timed-out request as a new transaction and execute a second charge (per `[S01:2]`). This directly violates the rule in `[S01:7]` that a customer must never be charged more than once for a single order.
