# Plan Review Report: Snapshot S01

### Advisory Review & Question Q01 Rationale

**Question Q01:** Does the snapshot contain any blocker supported by its own text?
**Answer:** Yes.

The plan contains a verified blocker arising from a mathematical conflict between its worker configuration, client-side rate limiters, and the vendor API contract ceiling:

1. **Vendor Ceiling and Penalty:** According to line `[S01:2]`, the API key contract imposes a combined ceiling of 50 requests per second, and exceeding this ceiling during any one-second window results in an immediate 24-hour suspension of the key.
2. **Strict Requirement:** Line `[S01:7]` mandates that the contracted rate must never be exceeded, because a 24-hour key suspension would halt live checkout address lookups for an entire day.
3. **Flawed Limiter Configuration:** Line `[S01:3]` states that exactly 12 worker processes run side by side without coordinating with each other, and line `[S01:4]` configures each worker with a client-side limiter capping it at 5 requests in any one-second window.
4. **Impact:** Because the 12 workers do not coordinate, their concurrent requests can reach up to $12 \times 5 = 60$ requests in a single one-second window. This potential peak of 60 requests per second directly breaches the contract ceiling of 50 requests per second, triggering the 24-hour suspension and violating the requirement in line `[S01:7]`.
