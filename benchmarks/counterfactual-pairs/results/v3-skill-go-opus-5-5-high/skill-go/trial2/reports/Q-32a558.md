**Rationale**

The plan's ordering breaks itself. Line 3 says the server keeps serving its 'Internal Root 2023' certificate until the switch on day 7. Line 8 removes 'Internal Root 2023' from every client's trust bundle on day 5. Line 2 says a client trusts the server only if the certificate chains to a root in its local bundle, and bundles are re-read every 15 minutes. So from shortly after day 5 until the day-7 switch, clients will no longer trust the 2023-chained certificate the server is still presenting. That violates line 1: "connectivity must never drop for any client."

Line 2 says open connections survive a reload. New connections and reconnections in the day 5 to day 7 window would still fail. The blocker follows directly from the snapshot's own text. Root removal should come only after the day-7 switch is confirmed.

Nothing else in the snapshot is a blocker:
- **Line 5:** The day-3 inventory gate on the switch is sound.
- **Line 7:** Both roots share one subject name, but staging showed that dual-root bundles accept certificates from each root.
- **Line 8, key destruction on day 5:** Destroying the key does not by itself cut connectivity. It does remove any way to reissue or roll back a 2023 certificate, which adds to the risk of the early timing. That concern sits on the same line, so it is folded into the blocker.
