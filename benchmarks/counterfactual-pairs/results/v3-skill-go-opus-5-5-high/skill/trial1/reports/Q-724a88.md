**Rationale**

The plan's own numbers exceed the contracted rate.

- **Line 3:** 12 workers run in parallel with no shared coordination, and the count stays fixed.
- **Line 4:** each worker may send up to 5 requests per second.
- **Combined ceiling:** 12 × 5 = 60 requests per second.
- **Line 2:** the contract allows at most 50 requests per second in total. Exceeding it in any one-second window suspends the key for 24 hours.

Nothing in the plan keeps the combined rate under 50. Line 3 rules out coordination between workers. Line 5 only stops retries from adding traffic beyond each worker's 5 per second, so the ceiling stays at 60. Line 6 rules out other users of the key, but that doesn't help, because the backfill alone can exceed the limit. Under this design, 60 requests can land in a single one-second window, which would breach line 7's requirement and could suspend the key used for live checkout lookups for a day.

This is a blocker supported by the snapshot text, and the arithmetic can be checked from the plan itself. One fix would be to set each worker's limit to 4 per second (48 total). Another would be to use a single shared limiter of 50 per second or less.
