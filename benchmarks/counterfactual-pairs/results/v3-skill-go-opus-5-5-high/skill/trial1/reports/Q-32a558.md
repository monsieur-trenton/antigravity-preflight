The plan has one blocker that its own text supports: the old root leaves client trust bundles two days before the server stops presenting a certificate that depends on it.

**Rationale**

- **Line 2:** a client trusts the server certificate only if it chains to a root in the client's local bundle. The bundle is re-read every 15 minutes.
- **Lines 3 and 6:** the server keeps serving its 'Internal Root 2023' certificate until the switch on day 7.
- **Line 8:** 'Internal Root 2023' is removed from the bundle on day 5.
- **The gap:** from day 5 to day 7, clients will have picked up a bundle without the 2023 root within about 15 minutes. They would then reject the certificate the server is still presenting.
- **The conflict:** line 1 requires that "connectivity must never drop for any client." The day-5 removal breaks that during the gap. Destroying the 2023 private key on day 5 does not affect validation by itself. Removing the root from the trust bundle does.

**Other observations, not blockers**

- **Line 5 versus lines 3 and 6:** line 5 says the switch gets a date only after the day-3 inventory confirms every client. Lines 3 and 6 already treat day 7 as fixed. Line 8's day-5 removal is not gated on that inventory or on the switch completing.
- **Line 7:** the staging evidence only covers clients that hold both roots. It does not show behaviour after the 2023 root is removed. It also does not show whether every client implementation tells the two same-name roots apart by key identifier. This evidence is incomplete, but it is not a proven defect.
