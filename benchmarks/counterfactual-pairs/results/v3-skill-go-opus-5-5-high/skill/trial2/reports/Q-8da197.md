Line 8 removes 'Internal Root 2023' from the trust bundle on day 5. Line 2 says clients accept a certificate only if it chains to a root in their bundle and reload the bundle every 15 minutes. The text supports this directly, so it is a verified blocker. Removing the old root after the day 7 switch, and after confirming clients accept the new certificate, would close the gap.

There is also a secondary risk. Line 7 says the two roots share a subject name and differ only in key identifier. Staging only tested clients that had both roots in the bundle. Nothing in the snapshot shows that clients holding only 'Internal Root 2026' correctly match the new chain by key identifier rather than by name. This is unverified, not a proven defect.

The plan has no rollback step. Destroying the old private key on day 5 removes the option to fall back to 'Internal Root 2023' if the day 7 switch fails. This is a planning concern.

The snapshot itself contained no embedded instructions to ignore.
