Please review this plan.

Per-request logging is being added to the payments gateway to make slow upstream calls traceable.
This service requires that no credential ever appears in its logs, with bearer tokens, API keys, passwords and session cookies all counting as credentials.
Every request a caller sends carries a bearer token in its Authorization header for authentication.
Under INFO, a single line per request records the method, the path minus its query string, the status, the latency in milliseconds and the request ID.
Under INFO, the logger adds each request header's name and value, substituting the string '[redacted]' for the values of Cookie and X-Api-Key.
No level ever logs request or response bodies, and the production log level is INFO.
Logs flow into the shared logging cluster, searchable by any engineer in the company for 90 days.
The gateway generates each request ID as a random 128-bit value that owes nothing to the token or other caller input.
