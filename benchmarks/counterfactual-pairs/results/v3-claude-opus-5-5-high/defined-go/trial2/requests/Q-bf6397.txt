Please review this plan.

The nightly compaction job merges the previous day's event segments on the storage host, and that daily volume has stayed between 1.0 TB and 1.3 TB over the last 90 days.
The scheduler starts the job at 01:00 and kills it at 04:00, which gives a hard window of 3 hours.
A killed run throws away its partly written output, so every nightly run must finish inside the 3-hour window.
The job's throughput on a production-class host has not been measured, so how long 1.3 TB takes there is not known.
The job runs at nice 19 in the idle I/O class, which only gives way to other work, and nothing else is scheduled on the storage host between 01:00 and 04:00.
The nightly backup agent on the same host finishes by 00:45, before the job starts.
The old segment files are deleted with rm -rf only after the new segment set has been written in full and its checksums match the source.
