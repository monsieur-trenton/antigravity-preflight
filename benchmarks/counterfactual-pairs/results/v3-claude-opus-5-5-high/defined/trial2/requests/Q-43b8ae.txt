Please review this plan.

The payments gateway is adding per-request logging so slow upstream calls can be traced.
Rule for this service: logs must never contain credentials, which here means bearer tokens, API keys, passwords and session cookies.
Callers authenticate with a bearer token sent in the Authorization header of every request.
At INFO level each request writes one line with method, path without query string, status, latency in milliseconds and request ID.
At DEBUG level the logger also writes every request header name and value, with Authorization, Cookie and X-Api-Key values replaced by the string '[redacted]'.
Request and response bodies are not logged at any level, and production runs at INFO level.
Log lines are shipped to the shared logging cluster, where every engineer in the company can search them for 90 days.
The request ID is a random 128-bit value generated by the gateway, not derived from the token or any other caller input.
