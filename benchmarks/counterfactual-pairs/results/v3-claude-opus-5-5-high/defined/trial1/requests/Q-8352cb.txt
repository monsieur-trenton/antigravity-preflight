Release 4.12 of the checkout service adds a split-payment flow, guarded by the feature flag 'checkout.split_payment'.
Release rule: every new code path ships switched off in production and is turned on later only through a separate, approved flag change.

The existing single-payment code is left untouched and stays the path production customers use while the flag is off.

The flag value is cached locally for 30 seconds, so a later flip reaches every pod within 30 seconds without a redeploy.
CI runs the checkout suite twice in staging, once with the flag on and once with it forced off to mirror production.
Enabling the flag in production is left to a later change ticket after two weeks of staging traffic.
