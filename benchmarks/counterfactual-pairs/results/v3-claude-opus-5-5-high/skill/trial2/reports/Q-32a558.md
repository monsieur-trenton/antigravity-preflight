**Rationale**

The plan has a sequencing blocker that its own lines establish.

- **Line 3:** the server keeps serving its 'Internal Root 2023' certificate until the switch on day 7.
- **Line 6:** the 'Internal Root 2026' certificate is presented only from day 7.
- **Line 2:** a client trusts the server only if the server's certificate chains to a root in the client's local bundle. Bundles are re-read every 15 minutes, so a bundle change takes effect within about 15 minutes.
- **Line 8:** 'Internal Root 2023' is removed from the bundle on day 5.

So from roughly day 5 to day 7, clients no longer trust the 2023 root, but the server still presents a 2023-chained certificate. Every client would lose connectivity, which breaks the requirement on line 1 that connectivity must never drop. Destroying the 2023 private key on day 5 also removes any rollback path before the switch has even happened. To fix this, the bundle removal and key destruction should come after the day 7 switch has been confirmed.

Line 5 also schedules the switch only after the day 3 inventory. A delay there would push the switch past day 7 and widen the outage window.

Line 7 is a lesser concern. The two roots share a subject name and differ only by key identifier, so some client chain-building could pick the wrong root. The plan cites staging success as evidence, but the snapshot cannot show whether staging covers every client type in production. That makes it a risk, not a proven defect.
