**The coverage rests on an unchecked claim.** The duplicate query was run only on rows created before 4.9 (line 6). For newer rows, the plan relies only on the line 5 statement that a "single code path" writes all emails. No evidence supports that. Bulk imports, admin tools, backfills, direct SQL or other services could have bypassed it.

**The stakes make this worth fixing.** Line 2 says a failure to add the constraint aborts the whole release. Running the same `GROUP BY ... HAVING COUNT(*) > 1` query over all rows before the release would close the gap. These are recommended changes, not proven defects.
