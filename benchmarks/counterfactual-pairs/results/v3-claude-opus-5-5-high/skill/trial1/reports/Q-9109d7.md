## Rationale

The snapshot contains no blocker. Its retention arithmetic and protection controls hold together.

- **Retention covers the 14-day window.** Line 4 says the oldest restore point can need a base backup up to 21 days old, plus all WAL written after it. Line 5 keeps both base backups and WAL for 28 days, which leaves a 7-day margin. The nightly deletion only removes objects older than 28 days (line 6), so it cannot remove anything a 14-day restore needs.
- **The 5-minute target is consistent on paper.** Line 2 says WAL is archived within 60 seconds of being written, which fits a target of 5 minutes ago. This depends on how "written" is read. If it means a segment is archived only once it is complete, a quiet period could leave recent changes unarchived for longer. The plan does not mention a forced segment switch on a timer, so this is unverified, not a proven defect.
- **No conflict between the access rules.** The deletion job (line 6) and the database hosts (line 7) are separate principals. The hosts have write-only access, and the job's delete rule is limited to expired objects. These two lines do not contradict each other.
- **Rehearsal covers only the old end of the window.** The monthly test restores to a point 13 to 14 days back (line 8), which does exercise the oldest restore path through a 14 to 21 day old base backup. It never tests a restore to a recent point near 5 minutes ago, so the 5-minute target is never shown in practice. This is a coverage gap, not a blocker.
