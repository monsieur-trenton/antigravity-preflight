**Rationale**

The plan's own timeline contains a blocker:
- **Line 3:** The server keeps serving the 'Internal Root 2023' certificate until the switch on day 7.
- **Line 8:** 'Internal Root 2023' is removed from the trust bundle on day 5.
- **Line 2:** Clients re-read the bundle every 15 minutes and trust only certificates that chain to a root in it.

So from day 5 to day 7, clients will reject the certificate the server is serving. Open connections survive, but any new handshake fails. This breaks the line 1 requirement that connectivity must never drop for any client. The private key is destroyed on day 5 at the same moment, so there is also no fallback once the problem appears.

Two smaller points:
- **Line 7 (note):** The roots share one subject name and differ only by key identifier. The only evidence that clients handle this is staging behaviour. Production clients may build chains differently, so this is unverified for the real fleet.
- **Line 5 (note):** The switch date is gated on the day 3 inventory, yet lines 3 and 6 already fix it at day 7. This is consistent only if the day 3 inventory passes. The plan says nothing about what happens if it does not.
