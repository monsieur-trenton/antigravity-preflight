From tonight, the nightly customer export writes its output to the bucket exports-prod under the prefix nightly/ instead of the old shared drive.
The export runs once at 01:00 under the service account svc-export, and a failed run is not retried.
The 09:00 release pipeline uses tonight's export as its input, and if the export has not completed, that morning's release is blocked and does not ship that day.
Yesterday a 1 KB object was written to exports-prod/nightly/ with svc-export's own credentials, the write succeeded, and an administrator then removed the object.
The bucket policy for exports-prod is kept in the infrastructure repository, and no change to it is pending or scheduled before tonight's run.
A lifecycle rule deletes objects in exports-prod after 7 days, which does not affect the release because the pipeline reads each export within 8 hours of it being written.
The export is written as a single object of about 30 GB, which is well under the bucket's stated limit of 5 TB per object.
