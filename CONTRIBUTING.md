# Contributing

Open an issue describing a concrete failure, expected behavior and the relevant release/runtime identities. Use synthetic examples and sanitized evidence; exclude project secrets and private source.

Run the offline checks in the README. CI has read-only repository permissions and calls no real model. Documentation changes should preserve explicit distinctions between advisory assessment, completeness, authorization and technical enforcement.

Runtime changes must update the package pins and receive affected offline/native qualification before being described as qualified. Passing process doubles is not native qualification. Do not silently replace a model, loosen stream validation, discard stopped attempts or rewrite a reviewer report to make its citations match.

Keep project-specific governance in project profiles. Do not add vendor binaries, authentication material, raw native streams, private qualification packets or large generated evidence trees to commits. Contributions are made under this repository's MIT license.
