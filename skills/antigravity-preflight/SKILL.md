# Antigravity preflight

Move detectable blockers, incomplete evidence, and integration failures ahead of the independent reviewer. Preflight is advisory: it cannot authorize implementation, replace an applicable database or independent review, or merge, publish, deploy, or activate anything.

The default route is a manual Antigravity handoff to **Gemini 3.8 Flash / High**, pinned to `gemini-3.8-flash-high` with High reasoning. Record the visible model/effort configuration and any unavailable runtime attestation; do not silently fall back or substitute Argon. Use one bounded review, with no automatic follow-up or multi-turn loop. Preparing a packet does not authorize sending it or launching a model; use the owner's task authorization. Mechanical local checks need no model.

1. Read the applicable project rules and declare `PLAN` or `DIFF`. Codex implements and runs local checks only when commissioned. Design review does not require invented implementation or execution receipts. Prepare the self-contained [packet](references/packet-template.md), including relevant unchanged contracts, invariant mapping, minimal fixture categories and sanitized test source/receipts. Keep large datasets in authorized out-of-band harnesses; domain schemas and fixtures belong in the task packet, not in this reusable skill.
2. Follow the [manual handoff protocol](references/manual-handoff.md) and [review rubric](references/review-contract.md). Gemini inspects supplied snapshots only: no edits, operational tools, delegation, database connections or execution. Detailed instructions express action bounds; they do not establish technical containment. Keep source omissions and deliberately unfinished work explicit.
3. Codex checks every inventory hash, source/question coverage and exact citation. Use the local [numbered-view and quotation checks](references/citation-checks.md) when preparing or checking a manual packet; these do not call a model or activate the CLI adapter. Record report completeness (`COMPLETE` / `INCOMPLETE`) separately from findings assessment. Missing required evidence prevents readiness; it does not by itself prove a code defect. A stopped or invalid response supplies no admitted advisory verdict.
4. Check every factual premise of each finding, not just the presence of its quotation. Record accepted / rejected / unresolved / needs-owner findings and reasons in the [decision record](references/decision-template.md). Correct accepted blockers only within current authorization. Preserve original, rejected and unresolved findings for the owner and independent reviewer.
5. Recommend `READY_FOR_REVIEW` only for a complete report with required gate evidence, independently resolved blockers and explicit risk dispositions. Hand off the exact final candidate, packet, original report and decision record to the separately authorized independent reviewer. Substantive candidate changes invalidate affected evidence; refresh only within authorization.

Read the project-owned review profile and governance documents. Use [the generic profile](references/project-profile.md) as a starting point. Keep domain taxonomy, database rules, role assignments and test commands in the project; they are not universal skill policy.

Read the [runtime runbook](references/runtime.md) when the owner commissions a CLI review or adapter work. The source owner activated the exact frozen agy 1.3.6 normal runtime on the qualification host, accepting the disclosed P5 independence risk. Publication does not activate CLI use on another host; establish that host's qualification and owner authorization first. Follow its pinned runner, normal qualification envelope, fresh-seed workflow and closing checks instead of the manual delivery step. Manual Gemini 3.8 Flash / High remains the default. The legacy schema adapter and P2 denial driver are not the activated review route. Future production code reviews still require a separately authorized independent review under project policy. Native observer development remains **PARKED**.

For an authorized new-runtime CLI attempt, follow [CLI update checks](references/cli-updates.md): capture current metadata before interpreting it, freeze the exact binary for the run, and qualify required capabilities and stream behavior. A version change alone is not a failure. Missing capabilities or changed semantics require a stopped result; never silently fall back to another model. This metadata helper does not activate automated CLI reviews.

An explicitly commissioned Argon / High native task may use the owner-activated r15 `argon-high` package (`gemini-4-argon-high`, effort `high`, `useG1Credits=true`). Read the [runtime runbook](references/runtime.md); never select Argon implicitly. A `COMPLETE` report is a self-report, not proof of reading. Unverified obligations required by the current gate prevent readiness; deferring them does not satisfy the gate.
